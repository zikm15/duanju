# 把 Afterglow 部署成可打开的网站

现有源码在 GitHub 的 `afterglow-v1-preview` 分支。仓库提供 `Dockerfile` 和 `render.yaml`，可用 Render Blueprint 部署。电脑或手机只需操作网页，不需要在 Windows 安装开发环境。

## 你需要完成的网页授权

1. 登录 [Render 控制台](https://dashboard.render.com/)，可以使用 GitHub 账号。
2. 新建 **Blueprint**，连接 `zikm15/duanju` 仓库，选择 **afterglow-v1-preview** 分支。如果仓库不可见，在 GitHub 授权页给 Render 访问该仓库的权限。
3. Render 会读取该分支根目录的 `render.yaml`。检查资源和价格，然后再确认部署。
4. 等服务状态显示为 **Live**，在服务详情页打开 Render 实际提供的 `https://…onrender.com` 地址。不要用猜测的域名。
5. 同一地址后加 `/admin` 是中文后台。在 Render 的服务环境变量中查看自动生成的 `ADMIN_PASSWORD`，自行填入后台登录页；不要将密码发到聊天或提交 GitHub。

## 配置已经准备好的内容

- Docker 多阶段构建：Node.js 24，自动安装依赖并构建前端；运行镜像带 ffprobe，支持实际 MP4 上传检查。
- Node 服务监听平台提供的 `PORT`；健康检查路径为 `/api/health`。
- SQLite 和上传文件写入持久盘 `/var/data/afterglow`，不随镜像更新丢失。应用启动后以非 root 用户运行。
- Blueprint 选择 **Starter 服务及 1 GB 持久盘**，这不是免费托管方案。以 Render 确认页面的实时价格为准。本次只提交配置，没有创建资源、开通服务或产生平台费用。
- 默认 `DEMO_MODE=true`：保留免费 / Basic / Premium 权限演示，真实 PayPal 支付仍关闭。
- 独立后台密码由 Render 自动生成。公网部署不会使用公开的 `afterglow-preview` 密码，页面也不会显示它。
- `TRUST_PROXY_HOPS=1` 供 Render 反向代理使用，正确识别 HTTPS 并设置 Secure Cookie。其他托管架构需要按实际代理层数调整，不要盲目开启。
- `autoDeployTrigger: off`：提交代码不会自动更新运行中的网站。需要更新时在 Render 控制台手动部署所需提交。

## 本版本的部署范围

这是供你试用的第一版测试网站，不是已开通收费的正式商用站。先检查播放器、手机切剧、收藏、后台上传、免费范围和会员权限，再继续加入真实内容与正式支付。

首次部署会创建新的演示数据。当前开发云端 `.runtime/` 里的记录和用户上传文件不会自动搬到 Render；确需迁移时，停服备份完整数据目录后再导入持久盘。代码包和镜像均不包含私有会话数据库。

SQLite 单实例与持久盘方案适合这个基础版本；本 Blueprint 不配置多实例横向扩展。1 GB 仅用于小规模验证，正式视频库需要规划存储容量、备份和对象存储。
